# Lista 1 (Prova 1) — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produzir a Lista 1 (Prova 1) como dois PDFs — folha do aluno (30 questões, sem respostas) e gabarito comentado — a partir de uma fonte Quarto única, com todos os números verificados no container.

**Architecture:** Um projeto Quarto isolado em `avaliacoes/` (fora do livro), formato **typst** (PDF sem LaTeX). Fonte única `lista-1.qmd`; a solução de cada questão vive num bloco `::: {.content-visible when-profile="gabarito"}`. Renderiza-se sem perfil (folha do aluno) e com `--profile gabarito` (gabarito). Todo número do gabarito sai de um chunk Python.

**Tech Stack:** Quarto + typst, Python (numpy/scipy/pandas/math), helper `formato.num` do repo. Tudo dentro do container (serviço `livro`).

**Spec:** `docs/superpowers/specs/2026-08-28-lista-1-prova-1-design.md` — leia junto com este plano.

## Global Constraints

Valores copiados verbatim do spec. Toda tarefa herda esta seção.

- **Cobertura:** só **Capítulo 1** (8 seções) e **Capítulo 2** (8 seções). A Introdução fica fora.
- **Total:** **30 questões** — **15 do Cap. 1 (Bloco 1, Q1–15)** + **15 do Cap. 2 (Bloco 2, Q16–30)**. Cada questão vale **0,5 ponto** (30 × 0,5 = 15 pontos = 15%).
- **Mix por bloco:** ~8 fechadas + ~7 abertas (16 fechadas + 14 abertas no total).
- **Fonte única:** `avaliacoes/lista-1.qmd`. A solução de cada questão é um bloco `::: {.content-visible when-profile="gabarito"}` que **começa com `### Resolução`**. Nenhuma segunda cópia do enunciado.
- **Manuscrito:** dados pequenos e auto-contidos no enunciado (tabela de 6–10 valores; contingência 2×2/2×3). **Nenhum** exercício "rode este código e reporte o número". Fechadas pedem **letra + justificativa**; abertas pedem **resolução completa** (fórmula → substituição → número → interpretação).
- **Fechadas:** 5 alternativas (a–e), uma correta; distratores por **erro conceitual clássico**; o gabarito registra a letra e **por que cada distrator falha**.
- **Integrativo:** um exercício pode cobrir várias seções. Garantir a matriz de cobertura (§9 do spec): **cada uma das 16 seções tocada por ≥ 1 questão**.
- **Números:** todo valor do gabarito sai de um **chunk Python** executado no container; formatação pt-BR via `from formato import num`. Nada de número escrito à mão no gabarito.
- **Privacidade:** `avaliacoes/` está no `.gitignore` (repo é PÚBLICO). **NÃO** commitar nada dentro de `avaliacoes/`. A verificação de cada tarefa é por **render**, não por commit. O único material versionado é este plano e o spec (sem respostas).
- **Caminhos:** `execute-dir: project` (cwd = `avaliacoes/`). Datasets do livro via `../dados/arquivo.csv`. Import do helper: `import sys; sys.path.insert(0, "..")` antes de `from formato import num`.
- **Não-vazamento (invariante):** no render **sem** perfil (aluno), a contagem de ocorrências de `Resolução` no output é **0**; no perfil `gabarito`, é **30** (uma por questão).

## Comandos de referência (dentro do container)

```bash
# folha do aluno (sem respostas):
docker compose run --rm --no-deps livro quarto render avaliacoes/lista-1.qmd --to typst

# gabarito (com respostas):
docker compose run --rm --no-deps livro quarto render avaliacoes/lista-1.qmd --to typst \
  --profile gabarito -o lista-1-gabarito.pdf

# no-leak (proxy independente de formato — o filtro de profile roda em qualquer saída):

  --profile gabarito -o _gab.md

```

### Task 2 (Fase 1b): Bloco 2 — Probabilidade e Distribuições (Q16–Q30)

**Files:**
- Modify: `avaliacoes/lista-1.qmd` (anexar o Bloco 2 após Q15)

**Conteúdo (instruções — questões reais autoradas localmente):**

- **15 questões**, ~8 fechadas + ~7 abertas, cobrindo as 8 seções do Cap. 2. Comece a numeração em **16**. Adicione o cabeçalho `## Bloco 2 — Probabilidade e Distribuições` antes de Q16. Cobertura mínima (spec §9):
  - **2.1** — interpretações de probabilidade + espaço amostral (fechada conceitual).
  - **2.2** — regras (complemento, adição, multiplicação, independência) sobre uma tabela pequena.
  - **2.3** — **condicional + Bayes** a partir de uma **tabela de contingência 2×3** (probabilidade total → inversão) e uma questão de **taxa-base** (falso-positivo) — arquétipo central; pelo menos 1 fechada com o distrator "sensibilidade = posterior".
  - **2.4** — **contagem** (permutação × combinação): 1 fechada que exige decidir se a ordem importa.
  - **2.5/2.6** — **escolha da distribuição**: um cenário de lote/amostra em que o aluno decide **binomial × hipergeométrica** (com/sem reposição), justifica e calcula uma probabilidade (chunk usa `stats.binom`/`stats.hypergeom`). Distrator: aplicar binomial onde é hipergeométrica.
  - **2.7** — **normal**: padronização (z), regra empírica 68/95/99,7 (distrator: regra invertida).
  - **2.8** — **cauda longa**: por que a intuição normal falha; pode integrar com 2.7 (padronizar num cenário e discutir a cauda).
- `stats.hypergeom(M, n, N)` = (população, sucessos-na-população, tamanho-da-amostra) — cuidado com a nomenclatura (ver `content/cap02/06`).
- Mesmos padrões da Task 1: dados pequenos, solução gated com `### Resolução` + chunk verificável, explicação dos distratores.
